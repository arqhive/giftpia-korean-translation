# 기프트피아 (GC, GGFJ01) 한글화 분석

작성 2026-10-01 · 1단계

## 판정: 조건부 가능

구조는 모두 풀렸고 왕복 재빌드가 바이트까지 일치합니다. 다만 두 가지 큰 작업이 필요합니다.
(1) 대사가 바이트코드 안에 직접 박혀 있어 스크립트 전체 역어셈블·주소 재배치 도구가 필요합니다.
(2) 일반 글자를 본체 ROM 폰트로 그리기 때문에, 실행 파일을 고쳐 디스크의 한글 폰트를 읽게 해야 합니다.
분량(일본어 약 25만 자)이 가장 큰 부담입니다.

## 분량

| 항목 | 값 |
|---|---|
| 대사 파일 | `giftpia.dat`(U8) 안 `evt/*.evt` 44개, 맵마다 1개(각 약 0.5MB) |
| evt 구조 | 리틀엔디언 오프셋 표(12구획) + 바이트코드. 구획 6(약 44만 바이트)은 모든 맵에 거의 같은 내용으로 중복, 구획 5·8은 맵 전용 |
| 대사 수 / 글자 수 | 고유 문자열 약 12,800개, **약 24.7만 자**(일본어, 추정치, 잡음 일부 포함) |
| 실행 파일 문자열 | `main.dol` 안 약 1,075개, 약 1.1만 자(메뉴·아이템·편지·오류 문구) |
| 글자가 박힌 그림 | `ext/etc.tpl` 메뉴 탭 12장, `ext/title.tpl` 로고 가나 8장 확인. 맵 텍스처·`item.dat`·영상은 **미조사** |

## 텍스트 인코딩

| 바이트 | 뜻 |
|---|---|
| `0x00~0x27` | 제어 코드(`0x0A` 줄바꿈, `05 xx` 색, `0x11` 아이템 이름 치환 등) |
| `0x28~0x7A` | 히라가나 1바이트: 글자 = SJIS `0x829F + (바이트 − 0x28)` |
| `0xA1~0xDF` | 반각 가타카나(전각으로 바꿔 그림, 변환표 `main.dol` 0x16B624) |
| `0x81~0x9F`, `0xE0~0xEF` + 1바이트 | Shift-JIS 2바이트(한자·기호) |
| 끝 | `01 00` / `02 00` / `01 0C` |

대사 명령은 `0x66` 뒤에 바로 텍스트가 옵니다. 디코더는 `tools/gtext.py`입니다.

## 재삽입

| 항목 | 결과 |
|---|---|
| ISO 무변경 왕복 | **바이트 일치**(MD5 `AC8F0574…` 동일), `tools/build_iso.py` |
| U8 무변경 재패킹 | **바이트 일치**(1,106개 전부 다시 넣음), `tools/u8.py build`. 규칙은 오프셋 순서, 32바이트 정렬, 0 채움 |
| evt 재패킹 | **미해결**. 텍스트 길이가 바뀌면 바이트코드의 절대 주소(점프 등, 파일 기준 LE u32)를 모두 고쳐야 합니다. 명령어 길이표를 실행 파일 해석기에서 뽑아 역어셈블러를 만들어야 합니다 |
| 폰트 | 일반 글자는 **GC 본체 IPL ROM 폰트**(Shift-JIS, 문구 `Ins. memory to load ROM font.`). `ext/font.tpl`은 28px 그래픽 폰트로, 가나·영숫자만 288칸이고 한자는 없습니다 |
| 한글 2,350자 | ROM 폰트의 한자 칸(JIS 1·2수준 약 6,300자)에 한글을 넣으면 들어갑니다. 대신 실행 파일을 고쳐 ROM 대신 디스크의 폰트 파일을 읽게 해야 합니다 |
| 그래픽 | TPL(I4·IA8·RGB5A3·CMPR·RGBA8). 디코더 `tools/tpl.py` 작성, 인코더는 아직 없음(이전 GC 프로젝트 것 재사용 가능) |
| 체크섬·서명 | GC 디스크라 없습니다. ISO 앞쪽 빈 공간이 약 401MB 있어 커진 파일을 옮겨 넣을 수 있습니다 |

## 위험 요소

- **바이트코드 재배치**: 역어셈블이 하나라도 틀리면 주소가 어긋나 멈춥니다. 무변경 역어셈블→재조립이 44개 파일 모두 바이트까지 일치하는지 먼저 검증해야 합니다.
- **바이트 길이 증가**: 원문은 히라가나가 1바이트인데, 한글은 전부 2바이트입니다. 같은 글자 수라도 바이트가 1.5~2배로 늘어납니다. evt는 재배치로 해결되지만, 실행 파일 문자열은 들어가지 않으면 문자열을 새 영역으로 옮기고 포인터를 고쳐야 합니다.
- **ROM 폰트 교체**: 폰트 읽기 함수를 실행 파일에서 고쳐야 합니다. 실기 Wii(Nintendont)가 같은 함수를 자체 패치하면 충돌할 수 있으니, 2단계에서 실기 확인이 필수입니다.
- **한자·히라가나 겸용 칸**: 1바이트 히라가나는 그대로 두고, 한글을 SJIS 한자 코드 자리에 배정합니다. 문장부호·숫자는 원래 칸을 씁니다.
- **분량**: 약 25만 자로 매우 큽니다. 이터널 다크니스는 영어 약 18만 자에서 취소했고, 천지창조는 분량 때문에 중단했습니다.
- **중복 구획**: 공통 구획 6이 44개 파일에 들어 있어 번역문을 44곳에 똑같이 넣어야 합니다(도구로 처리 가능).

- 배포 대상 환경: **돌핀 + 실기 Wii**(Nintendont 추정)
- 원본을 넣는 방식: ISO 재빌드(바뀐 파일만 교체), 배포는 파일 단위 패처

## 다음 단계(진행 시)

1. 실행 파일에서 스크립트 해석기의 명령어 길이표를 찾아 evt 역어셈블러를 만들고, 44개 파일 무변경 재조립이 일치하는지 검증합니다.
2. ROM 폰트 읽기 경로를 찾아 디스크 폰트 파일로 돌리는 패치를 만듭니다.
3. 2단계 출력 시험 대상: 첫 대사(「ポックルは「〇〇」を手に入れた！」 같은 공통 문구)와 메뉴 탭 문구 몇 개. 돌핀과 실기 Wii에서 모두 확인합니다.
